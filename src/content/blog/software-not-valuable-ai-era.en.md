> Source: [In the AI era, software is already worthless](https://www.v2ex.com/t/1238096) (V2EX)

## Core takeaway

The OP says pure software can barely build an advantage anymore. The community usually adds a sharper cut: **what devalues is the layer below the model kill-line**—tool shells anyone can vibe-code, settings junk, thin content sites.

We push the endgame further:

> **When agents are strong enough, software really is cheap—and so is most customization.**

Default model capabilities swallow features. Project-priced "change the UI / change the workflow" work collapses into conversational edits. What can still hold value: outcomes, liability, distribution trust, proprietary data and workflow memory, plus hardware, licenses, and supply-chain friction software alone cannot touch.

![Software shelf vs agent orchestration metaphor](../../assets/inline-software-not-valuable-ai-era-01.jpg)

## What the OP claimed

One line: pure software—for individuals and companies—struggles to build moats.

The mood underneath is clear: when shipping gets easy, willingness to pay drops. Some replies agree: if everyone can build it, people subconsciously refuse to pay.

## Community consensus: stratify first

Few people buy "all software is worthless," but the high-signal split is consistent:

| More likely to cheapen | Harder to cheapen soon |
| --- | --- |
| Tiny utilities, cleaner/settings shells, niche info sites | Vertical industry software, simulation stacks, long-lived pro tools |
| Local, low-dependency personal utilities | Large cloud services + regulatory barriers |
| "I can ship a hundred of these in a day" shells | Experience and edge cases built over years |

Portable line: **model capability is the kill-line**—software everyone can write loses price power; complex, reliable, situated software still sells.

Others remind: value always lived in product and service, not in a zip of code. Hardware + software bundles, production-hardened B2B polish, and willingness to maintain all push the moat outside "can AI write this."

![Kill-line stratification](../../assets/inline-software-not-valuable-ai-era-02.jpg)

## Why "everyone can cook, yet restaurants thrive" fails for software

Skeptics love that analogy. The counter cuts the key difference: eating is a hard need; most software is not. Restaurants also sell not cooking, better taste, and social ritual. Software is often replaceable by "vibe one up for now."

The only durable parallel is paying for **stability, taste, peace of mind, and trust**—and that is buying outcomes, not code.

## Where moats move

Nearly every strong reply points the same way:

- Business and operations beat code  
- Data + workflow + trust + domain depth + continuous learning replace feature stacking  
- Long-term maintenance gets scarcer once building is easy  
- Possible upside markets: software discovery, reviews, forks, API composition—scale still matters; not everyone must vibe from zero

Earnings-report skeptics note pro software and AI software stocks still rise. Do not confuse **commodity tools getting cheap** with the whole industry going to zero.

## Our endgame: customization gets cheap too

Most of the thread argues about "is it cheap *now*." The more useful frame is end-state layers:

1. **Feature layer:** notes, translation, CRUD, generic sites—swallowed by defaults.  
2. **Customization layer:** project fees for requirement changes compress into chat with an agent; margins collapse.  
3. **Still scarce:** operated outcomes and who holds liability; distribution that picks safely and stays compliant; proprietary data and workflow memory you keep when you switch agents; physical world, licenses, supply chains.

Builder implication: stop selling "another app / another custom job." Sell agent-ready capabilities, orchestration, SLAs, and services-shaped software—see [[lovable-future-saas-agent-capabilities|SaaS as agent-usable capabilities]] and [[software-engineering-splits-three|software engineering splits three ways]].

## Decision checklist

1. Is this below the kill-line? If yes, do not bet a standalone paid product on it.  
2. If you sell customization: assume the customer next year edits it with an agent—does your pricing still work?  
3. Prefer business loops, data flywheels, workflow memory, hardware/licenses, and provable maintenance liability.  
4. Shift the pitch from "we have features" to "we deliver outcomes that get cheaper as models improve."

Cheaper code does not erase value—**value simply leaves implementation and bespoke change requests.**
